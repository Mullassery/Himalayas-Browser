🎛️ Himalayas: Adaptive Feature Loading

Himalayas uses intelligent lazy-loading to keep startup under 500ms, then loads features on demand.

Feature Module Load Timing Size Trigger Impact on Startup
Core Runtime Startup (0ms) 8–12 MB Always Critical path (included)
Daemon & IPC Startup (0ms) 3–4 MB Always Critical path (included)
WebKit/Rendering Startup (0ms) 12–18 MB Always (lazy GUI) Daemon loads; GUI optional
DevTools First use (on demand) 2–3 MB User opens DevTools 0ms (lazy)
Extensions First use (on demand) 5–15 MB User enables extension 0ms (lazy)
AI/ML Models On demand (first inference) 20–50 MB First agent request 0ms (lazy)
GPU Drivers On demand (first GPU use) varies High-perf agent activates 0ms (lazy)
🎯 Lazy Loading Principle: "Never load non-critical at startup; everything else lazy-loads on first use. Keeps startup <500ms forever."

This is unique to Himalayas—mainstream browsers load all modules upfront, resulting in 2–3 second startup times.
